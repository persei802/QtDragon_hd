FACING UTILITY

This program creates a gcode file that can be loaded into Linuxcnc to run a rectangular facing operation. The actual area covered will be Size_x by Size_y plus half the diameter of the tool on all 4 sides. This means that the facing routine will not work in a pocket unless the tool diameter is taken into account.

  • The machine should be X and Y zeroed at the lower left corner of the workpiece
  • The program is designed to run the selected raster pattern at a Z value of 0 in machine units
  • The feedrate for Z travel defaults to 1/2 the feedrate entered for X and Y
  • The parameter units are set to whatever mode the machine is currently in, either metric or imperial

Validation of Inputs

  • checks that there are no blank entries
  • checks that the spindle RPM is between the min and max ratings
  • checks that the feedrate is less than the maximum feedrate
  • checks that safe Z travel > 0
  • checks that the tool diameter > 0
  • checks that stepover is not larger than tool diameter
  • checks for valid input fields
  • displays a toolpath preview without generating any gcode
  • the start point is marked with a green dot, the end point with a red dot
  • a final profile path is not shown even if that option is checked
  • a final profile is only shown when gcode is generated
  • checks for valid input fields
  • creates a gcode program according to the Raster setting
  • creates a temporary file and loads it to linuxcnc
  • invalid parameters are shown with a red border and the program will not be created
  • the temporary file is automatically deleted when Linuxcnc exits

  • creates a gcode program according to the Raster setting
  • opens a dialog window to get a file to save to
  • invalid parameters are shown with a red border and the program will not be created

WORKPIECE HEIGHT UTILITY

This program probes 2 user specified locations in the Z axis and calculates the difference in heights.

  • when checked, the SET buttons are enabled
  • this allows the user to automatically fill in the X, Y and Z parameters with the current position as displayed on the DROs.
  • when checked, the calculated height is automatically transferred to the Workpiece Height field in the main screen.
  • the X, Y and Z coordinates specify where the first probing routine should start, in current WCS
  • the X, Y and Z coordinates specify where the second probing routine should start, in current WCS

Parameter Validation

Before running the probe routines, probe parameters are checked to make sure no problems will occur. Any 2 points within the machine operating volume can be specified.

The units are set to whatever the machine units are defined as in the INI file.

  • search velocity must be greater than 0.0
  • probe velocity must be greater than 0.0
  • maximum probe distance must be greater than 0.0
  • retract distance must be greater than 0.0 and less than maximum probe distance
  • Z safe height must be greater than P1 Z height
  • P1 Z height must be greater than P2 Z height
  • probe parameters are read from SETTINGS -> PROBE and checked for validity
  • if any errors are detected while checking validity, the probe routine will not run
  • any errors detected will be highlighted with red text in SETTINGS -> PROBE
  • the machine will jog to the first location and then probe down and record the Z1 position
  • the machine then jogs to the second location and probes down and records the Z2 position
  • the difference in probed values is reported as Calculated Workpiece Height
Warning
 Setting incorrect values can lead to crashes into fixtures on the machine work surface. Initial testing with no tool and safe heights is recommended.

  • causes all jog and probe routines currently executing to stop

HOLE CIRCLE UTILITY

This program creates a gcode file that can be loaded into linuxnc to run a hole circle operation. It can use G81, G82 or G83 canned drill cycles by selecting the appropriate checkbox.

The center of the hole circle can be offset from the current XY zero point.

The Z zero should be set to the top of the workpiece to be drilled.

The parameter units are set to whatever mode the machine is currently in, either metric or imperial.

  • checks that drill depth is > 0

HOLE ENLARGE UTILITY

This program creates a gcode file that can be loaded into Linuxnc to run a spiral hole enlargement program. It is for cases where a hole that has already been made needs to be slightly enlarged for whatever reason.

Machining will begin at the current radius of the hole and will then proceed to spiral outward to the desired final radius.

The parameter units are set to whatever mode the machine is currently in, either metric or imperial.

Validation of Inputs

  • checks that the tool number is > 0
  • checks that the tool diameter is > 0
  • checks that the spindle RPM is within operating range and adjusts if necessary
  • checks that the start diameter > 0
  • checks that the final diameter > start diameter
  • checks that the number of spiral loops > 0
  • checks that the cut depth > 0
  • checks that the Z safe travel height > 0
  • checks that the feed rate > 0

If the parameters contain invalid fields, that field is shown with a red border.

RAPID ROTARY UTILITY

This program converts G-code from G94 (units per minute feed rate mode) to G93 (Inverse time mode). The main difference between these two modes is that in G93, for every linear or arc move (G1, G2, or G3), that command must also specify how much time it should take to make that move. Using G93 is advantageous when a move has both linear and rotary components. The reason is that linear moves have units of distance while rotary moves are measured in degrees and many CAM software packages only specify feed rates in distance units. However, if you had a rotation move at the same time as a linear move, the controller (e.g., LinuxCNC) would move both axes at the same rate. For this reason, inverse time mode is used.

This application does not alter any of the positions in the G-code movement commands. Instead, it converts from G94 to G93 by calculating the distance the tool travels for each line and using the last feed rate specified to calculate the time it should take the tool to complete that movement. For rotary moves, the program uses the Z-axis position (as the radius value) to convert from rotational units (angles) to distance. This allows for constant tool tip feed rates even for complex geometries and results in slower A-axis rotations when machining larger diameter sections of a part and faster A-axis rotations when machining smaller diameter sections.

Typical Workflow

  • Generate the g-code (.ngc) for your part using your CAM software with a compatible post processor.
  • In the Rapid Rotary utility, select the input file and output file by clicking on the filename fields.
  • If the Z0 point is the A axis, set Z0 offset to 0. If the Z0 point is the surface of the cylindrical workpiece, set the Z0 offset to the diameter of the workpiece.
  • Select either IMPERIAL or METRIC in the units combobox.
  • Select the wrap conversion type from the conversion type combobox
  • If all input parameters are valid, the CONVERT button will be enabled
  • Press the CONVERT TO G93 button
  • If the conversion succeeded with no errors, the converted file is saved and the SEND TO LINUXCNC button is enabled.
  • The converted file can be opened from the FILE page of the main menu or by pressing SEND TO LINUXCNC
  • Manually inspect and/or test the output .ngc to be sure there are no errors or bugs in the converted file and that it is safe to run on your machine.

Features

  • Supports up to four axes (X,Y,Z,A)
  • Supports G01, G02, G03 movement commands (G02 and G03 are not typically used in rotary jobs however)

Limitations

  • Requires a space between X, Y, Z, A, I, J entities in the G-code (e.g, X12Y34 is not supported, it must be X12 Y34) [this can be configured in your post processor
  • Requires the input file to use G94 (units per minute feed rate mode) and it must be specified in the preamble section
  • Requires G17, G18 or G19 (plane select) to be specified in the preamble section of the input file
  • If a comment is found on a line, denoted by '(' the rest of the line is ignored and the comment is copied into the output file

The file specified on INPUT FILE is read and parsed to convert G94 commands to G93 commands. The result is written to the file specified by OUTPUT FILE.

The converted file is loaded into Linuxcnc.

Z LEVEL COMP UTILITY

QtDragon can compensate for Z level height changes using it's own gcode generation code for probing. An external program like G-code Ripper is not required, but can be used if so desired.

Z level compensation is a bed levelling/distortion correction function typically used in 3D printing or engraving. It uses a HAL non-realtime component which utilizes the external offsets feature of LinuxCNC.

Whenever a gcode program is loaded:

  • zlevel determines the currently loaded program file and looks for a related probe result file
  • for example, if some_file.ngc is loaded, it looks for a file called probe_some_file.txt
  • if it exists, the data is read and sent to the compensation module via a shared memory structure
  • a surface map is created and displayed in the zlevel module
  • if the COMP ENABLE button is checked, the compensation module sends offset data to the Z axis

Creating a Probe File

  • from the FILE page, load the gcode program which needs to be level compensated
  • the X and Y dimensions are automatically calculated and shown in the parameter frame in the X and Y size fields
  • enter the number of desired probe points for each axis
  • ensure that the selected zero reference point is the same as that of the gcode program
  • before a program is saved or sent to linuxcnc, the input parameters are checked for errors
  • any errors that are found are highlighted with a red border

The input data parameters are checked and if found valid, a dialog box prompts for a save filename. The probe program is calculated and saved to the specified filename. If the returned save file name doesn't start with 'probe_', it is added. When the file is loaded and run, it will produce a file with the same name but ending with .txt. This is the compensation data file and contains the XY probe coordinates and the Z level at that location.

Surface Map

When a gcode program is loaded into linuxcnc, this module checks for a file of the same name prefixed with probe_. If found, the data is analyzed and a reference plane is calculated using a least squares algorithm. The reference plane is used to create a compensation map which is sent to the compensation subprogram via a shared memory structure and also to create a graphical surface map. The probed points and contour lines are overlayed on the surface map. Clicking on one of the points will show that points location and the probed Z value as well as the compensation amount that will be applied if Z Compensation is enabled.

Sample postgui HAL file for combined spindle raise and Z Level compensation

# load a summing component for adding spindle lift and Z compensation
loadrt scaled_s32_sums
addf scaled-s32-sums.0 servo-thread
 
loadusr -Wn compensate python3 lib/compensate.py
 
# Z level compensation
net compensate-on    compensate.enable <= zlevel.enable
setp compensate.scale 1000
 
# add Z level and scaled spindle raise level values together
net eoffset-count    scaled-s32-sums.0.in0   <= qtdragon.eoffset-count
net comp-count       scaled-s32-sums.0.in1   => compensate.counts
net zaxis-eoffset    scaled-s32-sums.0.out-s => axis.z.eoffset-counts
setp scaled-s32-sums.0.scale0 1000
setp axis.z.eoffset-enable True
setp axis.z.eoffset-scale 0.001

TOOL DATABASE

The tool database utility enables the user to store additional information about the tools listed in the LinuxCNC tool.tbl file. This extra information is kept in a SQLITE database. On startup, the program checks if the database exists and creates one if needed. If the database exists, it is updated with any new information in the tool.tbl file. If the tool.tbl contains tools not in the database, they are added. If the database contains tools not in the tool.tbl, they are deleted. Interaction between the handler program and the database manager ensures it is always synchronized with the linuxcnc tool table.

Usage

  • At LinuxCNC startup, a list of available tool icons is generated from any .png files found in the tool_icons folder.
  • The tool_icons must be .png images. This enables them to have transparent backgrounds.
  • The preferred icon size is 160 x 270 pixels.
  • Adding or deleting a tool in the Linuxcnc tool table is reflected in the database table.

Tool Table Buttons

Inserts a new tool table entry to the top of the list with the tool number preset to the value in the NEXT AVAILABLE field. The tool can be renumbered by editing the tool column of the tool table. Even though LinuxCNC allows duplicate tool numbers, the database does not. Adding a tool with a tool number already in the database will overwrite the previous data.

Removes the checked tool from the tool table and updates the database. The NEXT AVAILABLE field is updated and the tool table is reloaded into LinuxCNC. If there were multiple tools with the same number, they are all deleted.

The checked tool is virtually loaded into the spindle by a M61Qn command and the labels in the TOOL panel of the main page are updated. If the tool has an associated icon, it is also displayed in the TOOL panel.

A tool can also be loaded by clicking on a tool in the tree view of the database tab and pressing LOAD TOOL

The tool currently in the spindle is virtually removed by a M61Q0 command.

A file dialog pops up to select either a .csv file or .html file. The csv file can be imported to a spreadsheet application. The html file can be loaded from the FILE page or viewed in a web browser.

Tool Database Tree View

All tools from the tool table are shown in the tree view and organized by category. Tools are assigned to a different group by dragging and dropping onto the desired group or by selecting the tool, then selecting the group on the Group combobox pressing UPDATE TOOL DATA.

Tool Categories

Tool categories can be created and deleted to suit the user's requirements. To create a new category, click on the TOOL GROUP combobox in the Tool Geometry frame and type the name of the category. Pressing RETURN adds it to the tree view. To delete a category, first remove all the tools the select that category in the TOOL GROUP combobox. Then right click the combobox and select Remove group. The category is then removed from the tree view. A group can be deleted only after all the tools have been removed.

Tool Data

This frame contains information from the tool table as well as custom data. The data from the tool table is for reference only and cannot be modified from the DATABASE tab, only the TOOL TABLE tab, as these data are sourced from the LinuxCNC tool table. This data includes Tool number, diameter, Z offset and tool comment.

Material Data

Each tool can have specific parameters associated with a material. For example, the recommened feedrate could be different for MDF and steel. To add a new material, type the name into the material combobox and press Return. Then select a tool from the tree view and right click the Material combobox and select which material is to be associated with that tool. The specific data can be entered and saved to the database by pressing the Update Tool Data button. If a material is to be removed, the right click context menu has an entry to remove the selected material from the selected tool, but will not be deleted from the database until no other tools use that material.

Updating the Database

To store the custom data into the database, select a tool from the tree view, then enter all the pertinent data in the tool geometry frame and press UPDATE when done. A tool icon can also be selected. The image files must be stored in the tool_icons folder in the CONFIG directory.

Note
 The tool database file in the CONFIG directory is called tool_database.db. It is advised to maintain regular backups of this file. If it becomes lost or corrupted, all information the user has entered may be lost and will have to be re-entered in a new database.
